# 工单存储接口设计

本轮基于工单核心 PR #5，将内存存储从 `CaseService` 拆出。服务继续判断租户范围、工单状态流转和业务错误。模型、服务方法和错误语义保持一致。

`CaseStore` 按租户与工单 ID 读取快照和审计历史。创建操作将首条快照与审计一起写入，同租户的同一 ID 已存在时返回失败。更新操作只在存储版本等于期望版本时提交新快照与审计。版本不匹配时两者都保持原样。审计按版本顺序读取，返回值是不可修改的快照。

Spring 注入内存实现。内存存储在一次加锁操作内发布快照与审计，工单重启后仍会丢失。后续 MySQL 实现必须用条件更新和同一个事务满足相同契约。

验收由既有工单服务测试、Spring 健康接口测试及可复用的存储契约测试组成。契约测试覆盖租户分区、重复创建、版本不匹配、有序审计、拒绝无审计记录的写入和同版本竞争。数据库依赖、迁移和真实事务回滚测试留到 MySQL 适配器实现。
